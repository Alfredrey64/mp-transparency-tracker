# Simple Politics

A simple breakdown of UK politics: who your MP is, who funds them, how they vote and what the numbers say about the country, from official sources and in plain English. Independent and unofficial.

Designed and built by Alfred Reynolds.

## Running it

```bash
cd frontend
npm install
npm run dev
```

The data pipeline lives in the `fetch-*.js` scripts at the top of the repository. Run them by hand, or on the schedule in `.github/workflows`, to refresh what the site shows.

## Voice

Plain, calm and specific. Short sentences, everyday words, no jargon without an explanation and no spin. Where there are two sides, state both fairly.

## Identity

- **Name:** Simple Politics
- **Line:** UK politics, made simple.
- **Mark:** the Houses of Parliament as a flat white silhouette on indigo (`public/favicon.svg`, and `src/components/LogoMark.jsx`). The app icons (`favicon.svg` and the PNG sizes in `public/`) are drawn by `node scripts/build-icons.mjs`, with the mark smaller and nudged up and left so it looks centred; change the scale or position at the top of that script. After changing an icon, bump the `?v=` on its address in `index.html` and `manifest.json` so phones fetch the new one.

## Embeddable cards

Any answer, and any chart on a Britain in numbers page, has an **Embed** button that gives out an iframe for another website. The card is a second Vite page (`embed.html`, `src/embed.jsx`, `src/components/EmbedApp.jsx`) with no menu or search, at `/embed.html#/answer/<id>` or `/embed.html#/chart/<page>/<measure>`, with `?theme=dark` for a dark card. The address helpers are in `src/lib/embed.js`. `vercel.json` lets these two paths be framed by any site (`frame-ancestors *`) while the rest of the site still refuses to be framed.

## Speed and stability

- **Fonts** are served from this site (`public/fonts`, wired up in `src/fonts.css`, licences in `public/fonts/LICENSES.txt`), so no request goes to a font provider and the four fonts used above the fold are preloaded in `index.html`.
- **Caching:** `vercel.json` marks everything under `/assets` and `/fonts` as immutable for a year, since the file names change when the contents do. Pages and data are still checked fresh.
- **Page changes** run as React transitions (`App.jsx`): the current page stays until the next is ready, a thin line shows only if that takes more than a moment, and the new page opens at its top in the same frame. `lib/preserveScroll.js` keeps tabs and filters from moving the page, and `components/Loading.jsx` holds a page's height while its figures load.
- **After a new deploy,** a tab left open reloads once if a page file has gone (`lib/chunkReload.js`).
- **Size budget.** `bundle-budget.json` caps the gzipped size of the JavaScript and CSS loaded on first visit and of the largest single file. `npm run check:size` (run in CI after the build) fails if a limit is passed; raise a limit on purpose, in the same change, when a feature is worth it.

## Checking party positions

What each party promised (`src/data/answerPartyPositions.js`) and the headline lists on the party cards (`src/data/partyManifestos.js`) are written in our own words from the 2024 general election manifestos, which are still the latest UK-wide manifestos for these parties. The quickest check is the manifesto itself: download the party's PDF (the links are in `src/data/partyMatchEvidence.js`, `MANIFESTO_SOURCES`), extract its text (for example with `pypdf`) and search for the figure or phrase. Some PDFs put an odd character between words, so search with the spaces removed. On 26 October 2026 every figure in the party cards and in "what each party said" was matched against the text this way; all of them were found, the only ones that did not match first time being formatting differences ("£750k" for "£750,000"). A party is left out of a question unless the manifesto makes a clear commitment on it.

The "Which party suits me?" quiz keeps its scores in `src/data/partyMatchQuiz.js` and, for every score, a note and a manifesto page number in `src/data/partyMatchEvidence.js`, which the results page shows. A statement is a single claim a manifesto can be held against; where a manifesto is silent the score may lean by 1 at most. `src/data/partyMatchQuiz.test.js` checks that every score has a note, that silent manifestos are not scored strongly, that a person who answers exactly as a party does is matched to it first, and that the results make sense for left-leaning and right-leaning sets of views. Plaid Cymru's 2024 PDF could not be downloaded when this was last checked (the server refused the request), so its scores rest on the summary in `partyManifestos.js` and are not stronger than that supports; check them against the PDF when it can be fetched. `node scripts/check-links.mjs` checks every outside address in the source.

## Teacher mode

`/teacher` (`src/components/TeacherMode.jsx`) is a separate way to use the site for a class: a full-screen presenter (`src/components/teacher/Presenter.jsx`) that goes through five chapters one step at a time. The words are in `src/data/teacherMode.js` and are plain, neutral and checked (the party leaders were last checked on the date in `CHECKED`; they change, so recheck them before a term). Each story picture is drawn in `teacher/Scenes.jsx` from the pieces in `teacher/art.jsx`, every piece tagged with the step it appears on (`<B n={step}>`); `teacher.test.jsx` checks the pictures and the words have the same number of steps. The pieces are animated with GSAP, loaded only on that page. Teacher mode is not in the Learn menu: its entry in `sidebarSections.js` is marked `standalone`, which keeps it out of the menu groups (`siteMenu.js`) while search, page titles and the address still find it, and it has its own tile at the foot of the phone menu (`FOOT_TILES` in `SiteHeader.jsx`, under Privacy and beside Terms) and a link in the footer's About column. The things that move are small and deliberate: people breathe and blink, words rise into place one after another (`Words` in `Presenter.jsx`), a bill is stamped and confetti falls when it becomes a law and at the end of the quiz, a party's seats fill in on a 650-dot House of Commons, pieces tagged `stagger` pop in one by one (`useBeats.js`), and on the page a line draws itself between the five chapters and the first story plays on a loop while it is on screen. The class vote (`VOTE` in `teacherMode.js`, drawn by `VoteScene`) counts hands as the teacher taps. With reduced motion or a data-saving connection every one of these is switched off (`data-calm` on the presenter). Nothing on the presenter may move when you click: `e2e/teacher.spec.js` steps through every slide and the quiz and fails if the picture, the words or the buttons change place.

## Changing page

`swapPage` in `src/App.jsx` handles every page change. Where the browser supports View Transitions, it first fetches the next page's code (`src/lib/lazyPage.jsx`, so the page renders in one pass with no loading skeleton), then cross-fades old to new with the header held still (`html[data-vt]` rules at the foot of `src/chrome.css`). Elsewhere, or with reduced motion or Save-Data on, it falls back to a React transition and a short fade. Pages are registered with `lazyPage(LOADERS.key)`, not `React.lazy`.

## Bills in plain English

`src/lib/billPlain.js` turns a bill's official long title into plain points (one per clause) by swapping the drafting verbs and a few stock phrases, adding nothing. A clause it does not recognise is kept as written, marked "Aims to". The official wording is always shown beneath. Hand-written descriptions in `src/lib/billDescriptions.js` take priority.

## Money calculators and the classroom pack

`/calculators` has take-home pay (`src/lib/takeHome.js`: England from `taxBands.json`, Scotland from GOV.UK's 2026 to 27 bands) and stamp duty (`src/lib/stampDuty.js`, England and Northern Ireland). Both cite GOV.UK and need the rates updated by hand each tax year or after a Budget. `/funding` states who pays for the site and holds the funding log: add a row there before taking any money. ## Page addresses and search pages

Pages have real addresses (`/taxRates/vat`, `/answers/why-housing-expensive`, `/constituency/Holborn%20and%20St%20Pancras`). The code still writes them the old way, `#/taxRates/vat`, in links and history calls, and `src/lib/route.js` turns those into paths: it converts an old hash address to a path when the page opens (so every shared link keeps working), rewrites `history.pushState` and `replaceState` calls, and moves between pages without a reload when a `#/` link is clicked. Use `navigate()` from that file instead of setting `window.location.hash`. `App.jsx` reads the page from the path; `#/tax` and `#/budget` are aliases for the Overview and Where it goes toggles of the Taxes page.

Because the site is a single-page app, `scripts/prerender.mjs` (run after `vite build` by `npm run build`) writes a copy of the built `index.html` for every page in `routeEntries` (`scripts/build-seo-pages.mjs`: the sidebar pages, every answer and every tax), with that page's own title, description and share tags and a plain heading and introduction already in the page. The app replaces that text when it starts; a visitor sees something as soon as the HTML and stylesheet arrive and a search engine reads real text for each page. Addresses with no copy of their own (a seat, an MP, an old `/tax` link) are answered with the home page's HTML by the catch-all rewrite in `vercel.json` (Vercel serves a real file first, and only rewrites when there is none); `public/pre.js` hides the opening text in that HTML when the address is not the home page, so it does not flash up before the app starts. `sitemap.xml` lists the real pages. The older `/p/<page>` pages are still written, pointing at the real ones, so links already shared keep working; `/p/tax` and `/p/budget` are redirected.

`e2e/routing.spec.js` checks old hash addresses, aliases, links without a reload, back and forward, and names in a path. Run it, with the offline test, as `npm run test:site`.

## Working offline

`public/sw.js` is a small service worker (registered by `src/lib/offline.js`, production only). After a first visit the site opens without a connection: pages are network first with a saved copy as the fallback, built files under `/assets` and `/fonts` are cache first, and reads from the data service are network first with a five second wait before the saved copy is used. `src/components/OfflineBanner.jsx` shows a notice while the connection is down. `src/lib/serviceWorker.test.js` runs the worker against a fake environment. Change `VERSION` in `sw.js` to throw away everything saved so far. A page address that was never opened is answered, when offline, by the saved home page, which starts the app and shows the page the address names; `e2e/offline.spec.js` runs the built site in Chromium with the worker, goes offline and checks this. To try it on a real phone: open the site, use two or three pages, switch to flight mode, close the browser, open the site again and open a page you used, then one you did not; then add it to the home screen and check the shortcuts (touch and hold the icon on Android).

**Installing it as an app.** `public/manifest.json` makes the site installable: an icon set (with padded maskable icons, `icon-maskable-*.png`), the name and colours, and four home-screen shortcuts (Find my MP, Your council, Tax rates over time, Jargon buster; `src/lib/pwa.test.js` checks each opens a real page). `src/lib/install.js` catches the browser's install prompt (Chrome and Edge) as early as possible; `src/components/InstallApp.jsx` has an Install card in Settings that says how to install on the device in use (a button where the browser allows it, the Share then Add to Home Screen steps on iPhone and iPad), and a small banner on phones and tablets from the second visit that can be put away for good (`sp-install-dismissed` in local storage). Once the site is running as an installed app on an unmetered, fast connection, `offline.js` fetches every page's code once per build so the whole app works offline. It is not a store app; wrapping it for the App Store or Google Play (for example with Capacitor or a Trusted Web Activity) would be a separate piece of work.

## General elections

The General elections page (`src/components/GeneralElection.jsx`) has three tabs: the 2024 result, past elections since 1945, and the governments since 1945.

- **Past elections.** `src/data/electionsHistory.json` is built from Parliament's constituency results (UK Parliament, "UK General Elections Results 1832 - 2019", under the Open Parliament Licence; turnout and the 1945 and 1950 totals are the House of Commons Library's published figures, taken from UK Political Info and Wikipedia because the Library's own tables could not be fetched). Rebuild it with `node scripts/fetch-election-history.mjs <raw.json>` (about 13,000 page requests, a few minutes) and then `node scripts/build-election-history.mjs <raw.json> <hex2019.json>`. The hexagon layout for the 2010 to 2019 boundaries is `uk-constituencies-2019-BBC.hexjson` from Open Innovations (MIT). Seats are matched to hexagons by name, so maps before 2010 only colour seats that kept their name; the page says so. The Speaker is counted separately, and the 1950 national totals use the published ones because the constituency data differs by a seat or two. `src/lib/electionHistory.test.js` checks the totals against the published figures.
- **Governments.** `src/data/governments.js` is written by hand from events that can be checked (Acts, treaties, referendums, dated events) and does not rank anyone. The figures shown under each government come from the same ONS series as the Britain in numbers pages (`src/lib/governmentMetrics.js` chooses which, and how a spell in office is measured; a series that covers less than 90% of a spell is left blank).
- **Manifestos.** `src/data/manifestoPledges.js` only goes back to 1997. Each pledge was checked against the text of the manifesto (Lancaster University's UK manifestos copies for 2005 and 2015 to 2024; the 1997 text against two copies; the 2001 text against one unofficial archive copy, with Channel 4's record of that year's pledge card as a second check; the coalition's own programme from gov.uk for 2010) and each outcome against an official statistic, an Act of Parliament or a named independent check, with the source beside it. When adding a manifesto, keep to pledges that are specific enough to check, give the outcome with a figure or a date, and name the source.
- **Seat lookup and compare.** `src/data/electionSeatNames.json` (every seat name that appears in any election 1950 to 2019, with its winner and lead at each) and `src/data/electionMargins.json` (Labour's share minus the Conservatives', per seat on the 2010 map) are built by the same script as `electionsHistory.json`. The seat lookup (`SeatLookup.jsx`, postcode through postcodes.io or a seat name) and the compare tool (`CompareElections.jsx`, which matches seats by name and uses the usual two-party swing) both load them on demand. A seat renamed or created later only appears from when it got its present name.
- **Devolved elections.** `src/data/devolvedElections.js` holds seats, turnout and who led the government for every Scottish Parliament, Senedd and Northern Ireland Assembly election, taken from each election's results page; a test checks that every election adds up to the size of its chamber. Add the next election as a new entry (and update `led`).
- **Share cards.** `src/lib/electionSpecs.js` works out the card for whatever the page is showing (an election, a government or a devolved election); the Share button in the page header and in each result card use it.
- **How it works.** `ElectionsExplained.jsx` has a small invented example (clearly labelled) that switches between first past the post and D'Hondt, so the numbers there are not from a real election; the real examples beside it come from the election data.
- **Motion.** Blocks ease up into view once (`components/Motion.jsx`), numbers count up when they scroll into view, the seat chart's dots arrive in a sweep, and pages cross-fade. Only opacity and a short rise are animated, never a width or a length, and everything stops under `prefers-reduced-motion`. Keep it that way: nothing that grows from full or from zero to its value.
- **Map gestures.** `src/lib/useMapGestures.js` gives the seat maps (`ElectionMap.jsx`, `HexMap.jsx`) pinch-to-zoom on touch screens, Ctrl or Cmd plus scroll on desktop, zoom buttons, and press-and-hold to pin a seat's card without leaving the map.
- **Search.** The site search (`GlobalSearch.jsx`) also finds elections, governments, devolved elections and seat histories (`src/lib/electionSearch.js`), which open the matching General elections tab.
- **Prime Ministers.** When a new Prime Minister takes office, add a government to `governments.js` and end the previous one, and add them to `src/lib/governments.js`, which shades the Britain in numbers charts. `src/data/governments.test.js` checks the two lists agree.

## Taxes

The Taxes page (`src/components/TaxRates.jsx`, route `#/taxRates`, under Britain in numbers) is one page with a row of toggles at the top. It joins what used to be two pages, Taxes and spending and Tax rates through time; old `#/tax` links open the Overview (an alias in `parseHash` in `App.jsx`). It follows 24 UK taxes since 1945 wherever a record exists, with a government band behind each chart and a list of every change showing which government (and, where it can be named with confidence, which Chancellor) decided it. The toggles each have a one-line description under them, and the address carries the toggle and what is picked inside it:

- **Where it goes** (`#/taxRates/where`, `GovernmentBudget.jsx` shown with its own heading left out): how the government's spending is split, from health and welfare to defence. It was the Where taxes go page.
- **Overview** (`#/taxRates`, `TaxOverview.jsx`): the main rates today (`TaxToday.jsx`; picking one opens its history), a Coming up panel (scheduled changes across every tax and a countdown to the next Budget, `TaxComingUp.jsx`), then the Office for National Statistics figures for what the government collects and spends. That last part is `SectorPage.jsx` for the `tax` sector, shown with its own heading left out (`embedded`). Its share links (`#/tax/...`) still work.

- **Rates over time** (`#/taxRates/<tax id>`): a kind-of-tax and tax picker, then for the chosen tax its charts, a time-range choice, the list of changes, notes and sources. Charts with money in them have an **As set / In today's money** switch (`lib/priceIndex.js`: the Retail Prices Index before 1988 and the Consumer Prices Index after, both from the ONS, chained at 1988). Taxes with a matching ONS series also show **what they raise as a share of GDP** (`lib/taxTake.js`, `TaxTake.jsx`). There is an Embed button (`kind: "tax"` in `lib/embed.js`, drawn by `TaxCard` in `EmbedApp.jsx`) and a Share button (`lib/taxShare.js`).
- **Who changed them** (`#/taxRates/government/<id>`, `#/taxRates/chancellor/<name>`, `#/taxRates/budget`): changes grouped by government, by Chancellor (only where the Chancellor can be named with confidence) or Budget by Budget (only changes with a known decision date).
- **Compare** (`#/taxRates/compare/<line key>/<measure id>`, `TaxCompare.jsx`): any tax line above one of the national figures in `lib/governmentMetrics.js`, one shared crosshair, and a table by government. To add a measure, add it to `METRICS` there. The Compare over time page also lists the percentage tax rates (as a topic called Tax rates, `lib/taxRateSeries.js`) and the tax take.
- **What I pay** (`TaxPay.jsx`, `lib/payCalc.js`): what an employee on a chosen salary would have paid in income tax and employee National Insurance in each tax year since 1990, with the pay held at the same buying power or the same pounds. The rates and bands for every year are in `src/data/taxBands.json`, built from HMRC's rates, allowances and National Insurance tables. A pension slider (a percentage of pay, taken before tax) and the employer's National Insurance are included. It is still a simplified picture (one job, no other income, contracted in, England, Wales and Northern Ireland, no student loan), and it also shows where this year's tax goes, using the spending split in `src/data/publicSpending.js`, shared with the Budget page.
- **Sources**: sources, how a change is credited, and what is left out.

Other places the tax data shows up: the site search finds taxes and rates (`lib/taxSearch.js`); the Jargon buster has the tax terms; tax pledges in the manifesto data (`rates: [...]` in `src/data/manifestoPledges.js` and `src/data/promises.js`) show what happened to the rates they named between that election and the next (`PledgeRates.jsx`, windows in `lib/pledgeWindow.js`).

- **Data.** `src/data/taxSeries.json` holds one entry per rate as `[date, value, options]` steps (a rate holds until the next step; `null` means not charged). `options.ann` is the date the change was decided when that differs from the date it began (it picks the government and Chancellor credited), `options.note` is a short note and `options.p: "m"` means only the month is known. `src/data/taxCatalogue.js` says what each tax is, which lines go on which chart, the notes and the sources. A line with `kind: "allowance"` is a threshold or allowance, where a rise means less tax. A line with `intro: true` begins with the tax being brought in, otherwise its first step is only where our record starts (`introEffect` says whether bringing it in meant more or less tax). A panel with `real: true` gets the today's-money switch. A tax with `setBy: "scottish"` is credited to the Scottish Government, not a UK government. `src/data/taxEvents.js` holds the next Budget (shown with a countdown until the day) and the names of past Budgets.
- **Stories.** `src/data/taxStories.js` holds the short "story behind the changes" notes shown under each tax (`TaxStories.jsx`): what happened, who decided it, and the figures, with no verdict on whether it was a good idea. Every number a story quotes is checked against the series in `taxRates.test.js`, so a change to a series that breaks a story fails the tests. When a Budget changes a rate that a story quotes, update the story too.
- **Sources.** Wherever HMRC publishes a historic table it is the source: Rates of Income Tax (1990 on), Income Tax personal allowances, Rates of Surtax, National Insurance (1975 on), Rates of Corporation Tax (1971 to 2017), Inheritance Tax and Capital Transfer Tax tables, the Alcohol, Tobacco, Hydrocarbon Oils, Insurance Premium Tax, Air Passenger Duty and Environmental Taxes bulletins, the Capital Gains Tax statistics, the stamp duty table and the SDLT rate pages. Council tax is the MHCLG live table, and `src/data/councilTaxByCouncil.json` (Band D for each English council, 2010 to 11 on, from the MHCLG Band D table, built by `CouncilTaxLookup.jsx` into the Find your council box on the council tax page) comes from the same release. The standard rate of income tax before 1990 is from a Hansard written answer of 18 November 1977 and the Finance Act 1972. VAT, business rates and the top rate of income tax from 1973 to 1988 are from Wikipedia, checked against other sources, Scottish income tax is from GOV.UK and the Scottish Government, and the recent measures (2025 and 2026) are from gov.uk policy papers and Budget summaries. Each tax lists its sources on the page.
- **Who set it.** `src/lib/taxRates.js` credits a change to the government in power on `ann` (or on the day it began if there is none). A Chancellor is named only when `ann` is given, or the series is set on Budget day (tobacco), or the Chancellor had been in the job for at least 330 days, so a Budget set up by the previous Chancellor is not credited to the new one. Add `ann` whenever a rate was decided under a different government from the one in power when it began. `src/data/chancellors.js` lists the Chancellors.
- **Adding a change, for example after a Budget.** See the Budget day steps below. By hand, append a step to the series in `taxSeries.json` (the test checks the dates are in order, no value repeats, and any `ann` is not after the start date), and add a new tax or line in `taxCatalogue.js` if needed. When a Budget schedules future steps, add them with the future date and the Budget date as `ann`; they appear under "Already decided, not yet in force" until the day arrives. Add the Budget to `EVENT_NAMES` in `taxEvents.js`, and set `NEXT_BUDGET` to the next one (or null).
- **Budget day steps.** (1) `node scripts/read-budget-rates.mjs` finds the newest Budget's Overview of tax legislation and rates on GOV.UK, reads its Annex A and lists every rate that differs between the two tax years, with the series that probably holds it (it only prints; give it a page address to read a particular Budget, or `--all` to list unchanged rates too; the annex can take a few hours to appear). (2) Check each figure against the Budget documents, then add it with `node scripts/add-tax-change.mjs <series> <date> <value> --ann <Budget date>`, or put several in a JSON file and use `--file`. The script refuses unknown series, impossible dates, an announcement after the start date and a clash with an existing step, warns when the value is not a change, and writes nothing unless everything passes (`--dry` only checks, `--list` shows every series, `--event "2026-10-28=Autumn Budget 2026"` adds the Budget's name). (3) Set `NEXT_BUDGET` in `taxEvents.js` and add any new line to `taxCatalogue.js`. (4) Run `npm test` and `npm run check:tax`. The two scripts are tested in `scripts/budget-kit.test.js`.
- **Keeping it right.** `npm run check:tax` (also run every Monday by `.github/workflows/tax-data.yml`) reads HMRC's and GOV.UK's published tables and compares the newest figure in each with `taxSeries.json`. It prints each difference and fails, but changes nothing.
- **Left out.** Vehicle excise duty (the rate depends on engine size or emissions and registration date, and we could not verify a year-by-year record), fuel, alcohol and tobacco before the official tables begin, estate duty rates before 1975, Scottish and Welsh property and landfill taxes, tax reliefs, customs duties and the TV licence. The About tab says so too.

## Britain in numbers: issue pages

Inequality, Brexit, Defence, Education and Ageing and pensions are one page each, with a row of toggles (the address carries the toggle, for example `/brexit/trade`). Each takes its figures from a primary source and says which, with the date checked, on its Sources toggle.

- **Inequality** reads `src/data/inequalityData.json`, built by `node scripts/build-inequality-data.mjs` from the ONS household income and wealth tables, DWP Households Below Average Income and ONS regional household income. Headline sentences are worked out in `src/lib/inequality.js`, so text and charts cannot drift apart.
- **Inequality, Place tab** reads `src/data/inequalityPlace.json`, built by `node scripts/build-place-data.mjs` from the DWP's detailed Households Below Average Income tables (poverty and median income for each region, three-year averages; the script reads the zip with `unzip(buf, { binary: true })` from `xlsx-lite.js`), the ONS regional income tables (before and after tax and benefits, 182 local areas), the ONS wealth tables (25th percentile, median and 75th percentile by region) and the ONS tax and benefit tables (kinds of neighbourhood). The seat map (`InequalityHexMap.jsx`, loaded only when the tab is opened) uses `deprivationConstituencies.json` and `seatHexes.json`.
- **Inequality, Other countries tab** reads `src/data/inequalityAbroad.json`, built by `node scripts/build-international-inequality-data.mjs` from the OECD Income Distribution Database's open interface (no key). The OECD's UK figure differs from the ONS's, and the page says so; countries are compared only on latest figures from `RECENT_FROM` (2018) or later.
- **Defence** reads `src/data/defenceData.json`, built by `node scripts/build-defence-data.mjs` from the SIPRI military expenditure database (14 countries). The promises and the armed forces' numbers are in `src/data/defence.js`.
- **Education** reads `src/data/educationData.json`, built by `node scripts/build-education-data.mjs` from the Department for Education's open statistics API (key stage 2 and 4 results, the disadvantage gap index, free school meals, absence, special needs and education, health and care plans). The headline figures and fee caps are in `src/data/education.js`, and `src/data/education.test.js` checks the two agree.
- **Ageing and pensions** reads `src/data/ageingData.json`, built by `node scripts/build-ageing-data.mjs` from the pension rates in `src/data/ageing.js` and the ONS prices and earnings the site already holds (run the ONS fetch first so April's figures are there). The State Pension age tool is `src/lib/pensionAge.js`, tested against GOV.UK's timetable and its worked examples.
- **Defence** also reads the Ministry of Defence's quarterly service personnel workbook (worksheet 3a) and the latest four quarters of GDP, which `build-defence-data.mjs` fetches and saves in the same file.
- **Brexit** keeps its expert estimates, with sources, in `src/data/brexit.js`, read by hand from the original releases, and the referendum result by region (which adds up to the UK totals, checked in `src/lib/brexit.test.js`). Its charts and regional picker read `src/data/brexitData.json`, built by `node scripts/build-brexit-data.mjs` from the OECD (real GDP per head against the G7, the EU and others, 2016 Q2 = 100), the ONS series the site already holds (goods trade with the EU and the rest of the world, migration), HMRC's regional goods trade for the four nations, and the ONS mid-2025 population estimates (migration by region).
- **The NHS** (`/nhs`) reads `src/data/healthData.json`, built by `node scripts/build-health-data.mjs` from NHS England's "Incomplete Commissioner" waiting-time workbooks (the seven NHS regions, the latest month and the same month in the three years before), the ONS series already held (waiting list, A&E, ambulances, cancer, staff, long-term sickness) and the World Bank (health spending, doctors, nurses, beds). The NHS regions join some of the map's regions, which is why two places can show the same figure. Targets and standards are in `src/data/health.js`.
- **Net zero and energy bills** (`/energy`) reads `src/data/energyData.json`, built by `node scripts/build-energy-data.mjs` from DESNZ (final and provisional greenhouse gas emissions, regional emissions, Energy Trends electricity by fuel, annual domestic energy bills, international electricity prices, fuel poverty), Ofgem's price cap model (what the cap is made of, each period since 2017), the ONS consumer price index and the World Bank. The script finds the newest DESNZ release itself through GOV.UK's search, so it keeps working when a new release replaces the old. The carbon budgets set in law after the fourth, the targets, the latest price cap and the facts the arguments rest on are in `src/data/energy.js`, each with its source and date. The page is split across `Energy.jsx` (overview, arguments, sources), `EnergyEmissions.jsx`, `EnergyPower.jsx` and `EnergyBills.jsx`.
- **Trust in politics** (`/trust`) reads `src/data/trustData.json`, built by `node scripts/build-trust-data.mjs` from the OECD Trust Survey (2021 and 2023, which the ONS ran in the UK): trust in government, parliament, the civil service, local government and the courts, and whether people feel they have a say. The turnout, votes and seats come from the election results the site already holds (`electionsHistory.json`, `generalElection2024.js`). The British Social Attitudes figures are in `src/data/trust.js`, each as NatCen reported it and with the date.
- **Social care and childcare** (`/care`) reads `src/data/careData.json`, built by `node scripts/build-care-data.mjs` from the adult social care finance report (spending since 2005 to 2006, who pays, unit costs by region), the adult social care activity report, the survey of adult carers, Skills for Care's workforce statistical appendix (vacancies, turnover, pay, projections) and the Department for Education's funded early education and childcare statistics (through its open API). The newest release of each is found through GOV.UK's search. The facts the Department for Education publishes only as text (the parents' survey) are in `src/data/care.js` with their date. The page is split across `Care.jsx`, `CareAdult.jsx`, `CareWorkforce.jsx` and `CareChildcare.jsx`. England-only maps pass `ukLabel: "England"` so the map's text says England, not the UK.
- **Transport** (`/transport`) reads `src/data/transportData.json`, built by `node scripts/build-transport-data.mjs` from the Department for Transport (road traffic estimates, vehicle licensing, road conditions, road casualties, bus statistics) and the Office of Rail and Road's data portal (journeys, government support, fares, punctuality and cancellations, read from the portal's own table pages). The newest release of each is found through GOV.UK or the portal, and regional populations come from `brexitData.json`, so Brexit's script must run first. The facts about who runs trains and buses (the rail transfers and the Bus Services Act 2025) are in `src/data/transport.js` with their dates. The page is split across `Transport.jsx`, `TransportRoads.jsx`, `TransportRail.jsx`, `TransportBuses.jsx` and `TransportPlace.jsx`.
- **Devolution and the union** (`/union`) reads `src/data/devolutionData.json`, built by `node scripts/build-devolution-data.mjs` from HM Treasury's Country and regional analysis (identifiable spending per head and by function), the ONS's country and regional public sector finances (net fiscal balance, where a positive figure is a deficit) and the ONS's regional GDP. The newest release of each is found through GOV.UK or the ONS dataset pages. The 2014 referendum result, the 2022 Supreme Court ruling and the English devolution Act are in `src/data/devolution.js` with their sources, and the devolved election results come from `src/data/devolvedElections.js`. The page is split across `Union.jsx`, `DevolutionMoney.jsx`, `DevolutionEconomy.jsx` and `DevolutionPlace.jsx`.
- **Weekly refresh.** `.github/workflows/refresh-issue-data.yml` runs `scripts/refresh-issue-data.mjs` every Monday: it re-runs each build script above in order, runs the tests, and opens a pull request with any new figures (and a table of which steps worked) for a person to read. A pull request opened with the built-in token does not start CI, so the tests are run in the job and their result is in the pull request. Each file names the release and the date it was checked. ## Text contrast

Text must read against its background in both the light and the dark pages (4.5 to 1). Never put a bare accent or party colour on the page as text: use the helpers in `src/theme.js`.

- `readable(colour)` for coloured text (it mixes with the ink by just enough, separately for light and dark).
- `solid(colour)` for a fill under white text, `chip(colour)` for a fill plus its text (initials in a party-coloured circle), `onFill(colour)` when only the text colour is wanted, and `COLORS.accentText` for the accent as text.
- Do not lower the opacity of text (it lowers the contrast); use `COLORS.inkSoft`.

`e2e/contrast.spec.js` runs axe's colour-contrast rule over the issue pages and the pages that were fixed, in both themes (`npm run test:contrast`).

## Phone layout test

`e2e/phone-layout.spec.js` opens every page (the list comes from `src/pageLoaders.js`, so a new page is picked up automatically, plus the tabs listed in the spec) in Chromium at 320 and 375 px wide and fails if the page scrolls sideways, does not open at the top, has no single `h1`, or throws an uncaught error. It runs on every push and pull request as the "Phone layout" job in `.github/workflows/ci.yml`. Data requests are refused during the run, so the result does not depend on the network or on live data.

Run it locally with `npm run test:phone` (the first time, `npx playwright install chromium`). It builds the site and serves it on port 4175. If it fails in CI, the failure details are attached to the run as `playwright-report`.

## Tidy rows of boxes

`src/lib/balanceBoxes.js` (started from `main.jsx`, styled by `.bal-grid` in `index.css`) looks at every row of three to eight equal boxes after it is drawn, and where the browser would leave a lone or left-over box in the last row it lays the row out again: everything in one row if the boxes stay a sensible width, otherwise the fewest rows split as evenly as possible (5 becomes 3 and 2, 7 becomes 4 and 3) with a short last row centred under the rows above, and on a narrow screen with two to a row a lone last box runs full width. It never makes boxes narrower than 60% of what the page chose (and not below 130 px), tries the next layout if a box would overflow, and runs before the screen is painted. Put `data-no-balance` on a row to leave it alone. `planOptions` is unit tested in `balanceBoxes.test.js`; the layout audit fails if any row still ends lopsided.

## Watching the live site

`scripts/check-site.mjs` (`npm run check:site`, or `SITE_URL=... node scripts/check-site.mjs`) opens the live site the way a visitor would: key addresses must answer 200 within 15 seconds, `sitemap.xml` and `manifest.json` must be valid, and a real browser opens the busiest pages and fails on a script error, a failed request to the data service or the assets, the "Something broke on this page" screen, a page without exactly one heading, or a home page whose figures did not load or are over three days old. `.github/workflows/site-health.yml` runs it every three hours; if it fails it opens an issue labelled `site-health` (GitHub emails the repository owner) and when the check passes again it closes the issue. It needs nothing but GitHub. Error reporting from visitors' browsers (what a service like Sentry does) needs an account with that service and a change to the site's content security policy and privacy policy, so it is not set up.

**Keeping the content sound.** Three automatic checks watch for things nobody would notice by chance. `fetch-data.yml` runs as four jobs side by side and a last job that publishes (run one after another it took more than six hours and was cancelled every day from 26 October; the Lords step alone takes over two hours). `site-health.yml` also opens an issue labelled `data-stale` if no daily data refresh has been committed for more than 50 hours. `.github/workflows/content-check.yml` runs `scripts/audit-content.mjs` every Monday and opens an issue labelled `content-review` if a page of facts has not had its `checked` date renewed for 60 days, a saved data file has stopped being rebuilt, or a source link has gone (sites that refuse automatic visitors, with a 403 or 429, are not counted as broken). An MP who leaves the Commons is taken out of the MPs table by the daily refresh (`remove-departed-mps.js`, called at the end of `fetch-interests.js`): their declared interests, votes, written questions and news go with the profile, and their name stays on the Former MPs page, in the seat's history and in the governments they served in. It refuses to act if the list of current MPs comes back short or if more than 15 appear to have left at once, and it leaves in place anyone with a standards report or ministerial gift on record. Run `node remove-departed-mps.js` to see who it would remove, and add `--apply` to remove them. To renew a page, check each figure against its listed source, fix what has changed and update `checked`. CI supplies stand-in settings for the data service (`VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`), and the speed job starts `scripts/mock-data-service.mjs`, so the site can be built and tested without the real service.


## Layout audit, pictures and speed budget

`npm run test:layout` (`e2e/layout-audit.spec.js`, the "Layout audit" job in CI) opens every page at six sizes (phone 390, tablet portrait 820, tablet landscape 1180, laptop 1366, desktop 1920 and ultrawide 3440 px wide) and fails if anything pokes out of the page sideways outside a scrolling box, there is not exactly one `h1`, an image is broken, a button or link on a touch screen is under 24 px (not counting links inside a sentence, buttons that get the larger invisible tap area from `index.css`, or small targets with room around them, which is what WCAG 2.2 allows), a row of boxes ends lopsided, a long paragraph is wider than 1100 px, or an uncaught error is thrown. `npm run shots` (after `npm run build`) saves pictures of the main pages at five sizes to `screenshots/` with an `index.html` to look at them together (`npm run shots -- taxRates/vat glossary` for particular pages); CI attaches them to every run as `layout-pictures`. A machine can't judge looks, so the pictures are for a person.

`npm run check:speed` (the "Speed" job in CI) builds the site and runs Lighthouse three times on the built pages with the standard mobile settings, using `lighthouserc.json`. It fails if the median performance score falls below 70, accessibility below 95, best practices or SEO below 90, Largest Contentful Paint passes 5.5 seconds, Total Blocking Time passes 300 ms, layout shift passes 0.1 or the page weighs more than 1.2 MB. The limits sit just beyond today's results (performance 76 to 83, Largest Contentful Paint 4.2 to 4.8 seconds on a throttled phone, because the site draws in the browser), so they catch a slide, not a small wobble. Tighten them when the site gets faster.

## Accessibility

The site aims for WCAG 2.2 AA. What is in place, and how to check it:

- **Checker:** `axe-core` is a dev dependency. `src/a11y.test.jsx` runs it over pieces that can be drawn without a network. For a whole page (colour contrast, landmarks), run the dev server, open the browser console and load `/node_modules/axe-core/axe.min.js`, then `await axe.run()`. The pages were last checked in light, dark and phone layouts with no violations.
- **Landmarks:** one `main`, a named `aside` for the menu and one `nav` inside it. Every page has one `h1`.
- **Keyboard:** a skip link, a visible focus ring in both themes (`--focus-ring`), scrollable boxes and tables have a tab stop (`lib/a11y.js`, `scrollRegion`), and clickable cards that are not buttons use `keyboardActivate`. Pop-ups and the phone menu use `lib/useDialog.js`: focus moves in, Tab stays inside, Escape closes, and focus goes back to what opened it.
- **Screen readers:** loading and offline states announce themselves, search results announce how many there are, links that open a new tab say so, and charts have a table or text alternative.
- **Seating plan:** the Commons chamber has a list to choose an MP from as well as the clickable dots.
